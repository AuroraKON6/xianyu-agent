## 2. 失败证据与集成收口

R8发现HTTP导入把导入时刻当成观察时间，历史或演示报价可以在下游看起来新鲜。在绑定原报价实际时间和来源之前，不应直接增加真实影子样本或采购任务。

本轮最初12项失败测试实跑产生15个断言失败（含subtest）和3个缺失接口错误：旧报价重新变current，来源缺失/冲突仍可用，库存期限未重校验，Pi输入未携带来源，影子真实样本口径缺失。随后补入时间溢出、XLSX/时区、重放及正向守卫。不是把全部新测试笼统宣称为先红后绿。

完整HTTP回归另发现带ISO时间的粘贴CSV被旧键值解析器误判。独立回归先报`no sku column found`，修正为优先识别结构化表头后转绿，没有修改HTTP测试绕过粘贴入口。

并行[R9-I报告](CODEX_R9_SUPPLIER_INTAKE_2026-09-23.md)记录的3项HTTP导入错误已被上述修复覆盖；另有浏览器偶发抽到6665禁用端口，现将测试监听限定在49152-65535范围并持续持有套接字，避开先找空闲端口再重新绑定的竞态。保留R9-I的历史失败报告，本次在稳定源码窗口重跑全部1489项，包括23项准入评估、15项浏览器验收，通过后才标软件PASS。

没有引入新数据库、调度器、订单状态机或交易执行入口。

## 4. 关键回归

1. 实际观察比导入早5分钟，两者分别落库，重载不变；重复同内容导入复用快照，不刷新旧时间。
2. 缺失时间、无时区、未来时间、缺失/过期截止、未知来源、空引用不可成为可售库存。
3. supplier_original与明确demo备注冲突时demo优先；历史无元数据不自动继承资格。
4. 元数据与顶层observed_at不一致拒绝；截止恰等于now即过期；极端时区日期溢出保持未知而非崩溃。
5. 库存登记可售10，到期读取/重建可售0、锁定拒绝；商机ready重评估后paused。
6. Pi已提交报价数和来源时间合格数分开，demo输入可回放但不变成真实合格证据。
7. 影子观察前撤销批次：total=1、real_source_samples=0；重复tick不新增。
8. 正向声明路径记录一次，重建观察器后不重复；provider_verified与autonomy_authorized均false。
9. 游标落盘失败重放保留最初来源事实、不重写历史裁决、不重复计数；后来撤销不表示现在仍可用。
10. 7天/100条正向门槛测试只是临时目录人工夹具，即使布尔计数达标也不授权执行；不算真实经营样本。

原正向采购、库存、利润、HTTP薄链和失败恢复演练改用明确声明来源的测试夹具。`tests/quote_fixtures.py`仅用于测试，生产没有自动补真实来源的迁移或兼容放行。

## 6. 保留的边界

- supplier_original/real只是声明，不核实供应商身份、材料真实性或原单元格与历史归一化结果等价；provider_verified不变为true。
- `business_eligible_offer_count`只表示报价时间/来源结构门禁通过，不包括全部商业条款、人工批准或外部模型数据许可。
- 准入评估的身份、权限、售后等额外声明尚未作为持久批准接入所有旧业务入口；非空source_reference或只读ready报告都不能放行交易。
- 商机过期转paused发生在重评估时，没有新增定时自动暂停；影子观察独立重查来源时间与批次。采购仍走既有批次、库存、人工门禁。
- 来源合格数是观察时刻、当前应用数据范围内的结构性计数，不是认证供应商数、真实成交数或按策略独立验证结果。正式试运行须绑定指定账号/策略/授权版本，不能拿全局历史数量直接发布。
- JSON单进程互斥/最终一致性边界不变；本轮服务重建不是进程强杀或跨进程事务证明。
- 原`test_wp08_script.py`仍有未关闭文件ResourceWarning，无测试失败；未顺手修改无关测试。测试中的REAL_RUN_OK输出使用mock-model，不是本轮真实调用。
