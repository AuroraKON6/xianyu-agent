## F1 / P1：成功返回后的证据写盘失败仍导致消费漏账

位置：`E:\闲鱼\xianyu\xianyu_agent\pi_jobs.py:709`、`:712`。

当前顺序是模型返回 → 输出校验 → `_write_evidence_file` → `model_usage.record`。记账虽然前移到了 complete 之前，仍晚于证据文件写盘。磁盘满或权限失败发生在证据写盘时，已发生的模型消耗没有任何 ledger 条目；新建 ModelUsageLedger 重读文件后仍为零。

独立探针：创建临时 runner/job；FakePi 正常返回15 tokens；仅把 `_write_evidence_file` 替换成抛 OSError；异常之后新建 ledger 实例读取。

```json
{"probe":"evidence_write_failure_after_model","model_calls":1,"ledger_entries_after_reload":0,"used":0}
```

这直接否定“各写盘失败窗口均已覆盖”和“完成前记账即可崩溃不丢账”的强结论。现有新增用例覆盖了逻辑拒收、无效输出、prompt异常，但没有覆盖该成功返回后的证据写盘失败。

修复要求：把消费记录与业务输出写盘解耦，至少保证证据/决策/完成状态写失败不阻断已知 usage 入账。还需定义账本本身写盘失败或模型返回后进程退出时的保守恢复：调用前持久化 attempt 标识及未结算状态，持久化失败不得出站；调用后结算失败保留未知负债并阻断不安全重试。只交换两行顺序不能证明所有崩溃窗口闭环。

验收：对证据文件、usage ledger、决策文件、job完成记录分别注入写失败；重启后查询 attempt 状态、账本及下一次门禁。已知消耗只记一次，未结算不能变成免费额度。允许明确标识“未知”，但不能将缺失条目当成没有调用。测试必须检验实际持久化内容及重试行为，不只检验异常被捕获。

## F2 / P2：已存裁决的早返回会永久跳过缺失额度

位置：`E:\闲鱼\xianyu\xianyu_agent\shadow_observer.py:121`、`:144`、`:147`。

顺序为 log裁决写入 → shadow_usage写入 → cursor写入。新增早返回解决了最后一个窗口的重复累计，却破坏了中间窗口恢复：若 log 已成功、usage 写盘失败，重启后 `_record` 发现已有 log 就 return，不再补齐额度；随后游标可以推进，漏账永久化。

独立探针：日影子额度100，事件A报价60；在允许裁决已保存后让 `_shadow_usage._persist` 抛 OSError。新建 ShadowObserver 重读磁盘并重试A，再提交事件B报价70。

```json
{"probe":"saved_verdict_missing_accrual","allowed":1,"usage_rows_after_restart":0}
{"probe":"subsequent_event_exceeds_daily_100","allowed":2,"total":2,"usage_rows":1}
```

60+70>100，本应拒绝第二条影子动作，实际两条都被允许。此处是影子授权结果与统计失真，不代表已发生真实资金支出或平台操作。

修复要求：已存裁决不能等同于整个事件提交完成。保存足够的不可变事件数据，包括裁决、mandate、金额及原业务日；重放时复用裁决，同时幂等补齐缺失额度，再推进游标。可采用单一事件日志派生额度，或有明确恢复状态的多阶段提交。不能只删除早返回重新评估，否则会引回前轮重复累计或裁决漂移。

验收：log写失败、log成功usage写失败、usage成功cursor写失败三个窗口逐一测试；每个窗口重启后重放至少两次；事件A只占一次60，事件B的70被拒。跨日重放保留原事件归属日，不把旧裁决重新累计到新日。原有“60+70≤500两条允许”的正常场景继续通过。
