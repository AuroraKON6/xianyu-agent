## 2. 状态和风险处理

- 默认锁定，不自动读取对账数据；服务端仍默认关闭。凭证只发送至同源三个对账接口的Authorization头，不进入普通控制台API封装、请求体、URL、日志、回执或浏览器存储。禁用携带Cookie、跟随重定向及请求缓存。
- 密码框在解锁开始时清空。普通锁定清除凭证和面板内容；`pagehide`清除内存，重载不会恢复解锁状态。这是应用行为，不保证浏览器扩展、外部密码管理器或操作系统不会记录内存。
- 原业务日、attempt、tokens和证据由提案绑定；operator来自服务端。预览不写账，修改输入撤销预览和确认。
- 最多等待30秒；双击不增加请求。只有收到与当前job/attempt、消耗、resolution、幂等键及批准摘要匹配的回执才显示成功。
- 网络中断、503、不完整或不匹配回执保持“结果不明”：表单与列表被冻结，保留同一个序列化请求，不能自动换键或修改证据重试。
- 提交中也可立即清除凭证并停止客户端等待；服务端可能已提交，原请求仍仅保留于页面内存。重新认证后只能原样重试；响应丢失后的真实接口重放返回原receipt，账本文件不重写。
- 404/409/422撤销旧确认，需要人工核对及新预览；401/403清除凭证，需要同一操作者重新认证。
- 释放固定0但仍须独立未发送证据；出现模型输出时后端拒绝释放。legacy/孤立/活跃记录不给选择按钮。已结算不代表解除其他unknown、日预算或任务门禁。
- 所有动态远端文本通过`textContent`展示，XSS样例只显示文本。对账不创建有效业务决策、不恢复原任务、不自动调用模型。

7. HTTP 200但回执不完整不能显示成功。
8. 小数tokens不发预览；有模型输出的释放被真实后端拒绝。
9. 预览后服务端job变化产生409，不落账；重新预览后才可确认。
10. 双击仅一个提交。
11. 注入HTML仅显示文本；缺attempt的legacy不能选择，其他unknown仍保留。
12. 错凭证/关闭服务不解锁。
