# GLM 项目验收矩阵与证据要求

日期：2026-10-11。配套：[总计划](GLM_PROJECT_MASTER_PLAN_2026-10-11.md)、[接手入口](../../GLM_HANDOFF.md)。

本矩阵含 85 个验收项，都是对 G0-G5 新增工作的要求，不是已执行结果。初始状态统一为 NOT_RUN；历史功能/测试可复用，但须指向本包版本重验。执行结果写在 `docs/acceptance/` 的分包报告中，不把这份要求表改成缺少证据的勾选表。

## 1. 证据与状态

| 标记 | 层级 | 说明 |
|---|---|---|
| S | 服务/契约 | 临时目录内确定性测试，不调用真实平台或付费模型 |
| H | HTTP 集成 | 起隔离真实应用，用实际路由和持久存储，不以只测函数代替 |
| U | 浏览器 | 真实 console 资产及交互；后端是真实隔离服务还是 fixture 必须说明 |
| P | 进程/存储 | 子进程、重启、实际写盘失败/事务故障注入；标明注入层级 |
| R | 真实资料/通道 | 有来源、获准的真实输入或实际请求；示例、mock、空响应不算 |
| B | 商业事实 | 指定账号/SKU 的平台与供应商回执、付款/回款和用户批准 |

一个验收项含多个层级时分别报告，S/H/U 通过不能覆盖 R/B 未做。输出 PASS、FAIL、NOT_RUN、WAITING_INPUT 或 NOT_AUTHORIZED，附命令/操作、输入、期望与实际、时间、版本和证据路径。

人工核验材料标明来源范围；对话/订单/模型原始记录应脱敏，不把 Cookie、密钥、完整地址或隐藏推理写入报告。

## 15. 黄金样例与演练约定

### 15.1 金额样例

以下仅是明确的人工构造测试输入，不是费率建议或真实报价：

```text
同一单位、CNY、已明确数量与地域。
预估售价 300；采购 160；供应运费 20；包装 5；平台费用 9；可归因成本 4。
税费在本夹具中显式 not_applicable，并给出“测试假设”理由。
预期退货损失准备 12。
预计贡献利润 = 300 - 160 - 20 - 5 - 9 - 4 - 12 = 90。

真实事实模拟：按上述售价回款，已实际发生支出 198，则已结算收支差额 102。
售后期是否结束单独展示，不因收支差额为正即宣布最终经营结论。
之后部分退款 50，假定没有费用退回或新增支出，则收支差额 52。
不能再扣一次未实际发生的 12 元准备，把差额伪写为 40。
```

成本费用/退款返费规则改变时重新给定输入和期望，不把此夹具写入生产表单默认值。

### 15.2 库存样例

```text
实际可用 10，首个有效采购预留 4 -> 可用 6。
同销售单重复提交 -> 仍为 6，不产生第二有效采购。
取消先赢 -> 锁归还后 10，登记供应商单必须失败。
登记先赢 -> ordered，取消必须转人工/售后，不得直接归还库存。
对账遇到正在创建且未落盘的采购 -> 等待同一同步域，不得误释放。
```

### 15.3 数据来源

- 单元与演练数据必须留在隔离目录，报告标 synthetic/fixture；必要的正向门禁夹具不因此成为真实材料。
- demo/未知来源不能混入真实报价统计、策略有效样本和商业验收。
- 真实报价提供给外部模型前须有批准用途和明确调用预算；测试默认禁用真实模型。
- 时间使用可注入受控时钟进行测试；生产接口不能通过用户回拨 now 绕过到期。
- 进程内重建 store、真实子进程退出、模拟 SIG/kill、数据库断连必须分别说明，不能统称“断电恢复已验证”。

## 17. 停止发布条件

任一关键金额错算、跨账号使用、来源/批准失效未阻断、重复外部动作、未知结果盲重试、证据丢失、恢复误释放、测试写入 live 或不能解释的资金差异，均阻止对应动作上线。先复现修复并回归，不用更多通过用例稀释失败。

没有真实资料/订单仅阻止相应 R/B 验收，不阻止继续完成不依赖它们的隔离工程。最终不以 85 项表格全部填字为完成，而以对应层级的可复验证据为完成。
