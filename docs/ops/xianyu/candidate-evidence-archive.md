# 闲鱼候选证据存档 SOP

本 SOP 解决一个具体问题：一品启动包中的“证据引用”不能只是操作者手填的路径或网址，而必须指向系统实际保存、可校验、与候选绑定的原始文件。证据存档用于证明“当时看到了什么”，不会自动证明供应商陈述真实，也不会替代人工核验和审批。

## 1. 五类必备证据

| 类型 | 应保存的内容 | 必须能对应的候选事实 | 时效 |
|---|---|---|---|
| `supplier_quote` | 精确 SKU 的商品页、报价单或脱敏沟通记录 | 采购单价、运费、MOQ、供应商简称、SKU | 24 小时 |
| `supplier_stock` | 精确 SKU 的库存页或供应商库存确认 | `in_stock/limited`、可发数量、SKU | 24 小时 |
| `supplier_fulfillment` | 发货时效、无价格信息发货、退换、错货和破损责任条款 | 最长出库小时数、退换政策、责任归属 | 条款变化即重传 |
| `image_rights` | 自摄原图、供应商书面授权或许可凭证 | 图片来源、权利类型、可使用范围 | 权利或素材变化即重传 |
| `market_baseline` | 同一次观察中的至少两个可比闲鱼商品页或一份合并观察记录 | 两个不同链接、价格区间、需求信号 | 72 小时 |

一个类型同一时刻只能有一份 `active` 证据。市场基线需要覆盖两个竞品时，可上传一份 PDF、长截图或脱敏 Markdown 记录，并在启动包中分别填写两个实际链接。

## 2. 上传前检查

1. 确认候选是一个精确商品和精确 SKU，不要给占位候选 `T/test` 上传正式证据。
2. 截图或导出文件时保留商品名称、SKU、规格、价格/库存/条款和观察时间等判断所需区域。
3. 裁掉或涂黑 Cookie、token、密码、手机号、身份证号、收货地址和支付凭据。文本文件含这些值会被系统直接拒绝。
4. 图片权利证据必须来自自有素材、供应商明确授权或有效许可；竞品图片和文案不能当作自有素材。
5. 文件观察时间填写“实际看到该页面或收到该文件的时间”，不能填写未来时间，也不能用上传时间冒充观察时间。

支持 `PNG/JPEG/WebP/PDF/HTML/TXT/MD/JSON`，单文件上限 10 MiB。压缩包、Office 可执行内容和伪装扩展名会被拒绝。供应商或商品 URL 可以包含普通数字商品 ID，但不能包含用户名、密码、token、Cookie、API key、session key 或签名凭据参数。

## 3. 控制台操作顺序

1. 打开 `http://127.0.0.1:8788/console`，进入「倒卖机会验证」。
2. 在目标候选卡片点击「一品启动包」。先填写商品、SKU、供应商、价格、库存、履约、图片权利和竞品等事实字段。
3. 在「候选证据存档」选择证据类型、实际观察时间和文件；来源 URL、备注是可选的，但应足以解释文件对应哪个 SKU 和哪个判断。
4. 点击「上传并绑定」。系统先保存不可变文件，再把生成的 `artifact:cea_...` 引用绑定到当前候选，最后激活证据。
5. 在存档列表确认状态为 `active`、完整性为通过，并核对文件名、观察时间、字节数和 SHA-256 前缀。
6. 按五种类型重复上传。五个证据引用输入框由系统生成且只读，不能人工粘贴路径或网址冒充存档。
7. 保存其余启动包事实并重新打开。报价、库存和市场观察时间必须与对应活动证据的 `observed_at` 一致。
8. 完成当前账号+类目商业条款和利润重算后再跑 Agent 评审，最后由操作者批准当前证据指纹。

上传任何新证据都会形成新证据修订并使旧人工批准失效。这个失效是预期行为：应当重算、重评和重新批准，而不是恢复旧指纹。

## 4. 不可变和替换规则

上传采用四步状态流：

```text
校验文件 -> pending 存档 -> 绑定候选并写入规范引用 -> active
```

- 新文件激活后，上一份同类型证据变为 `superseded`，旧文件不删除，审计链仍可查看。
- 相同活动文件重复上传是幂等操作，不会重复创建存档。
- 已被替换的旧字节不能重新激活为“新证据”；若事实重新出现，应重新采集带当前时间和上下文的文件。
- 文件已保存但候选绑定失败时，记录变为 `orphaned`，不能通过门禁，也不会覆盖活动证据。
- 存档按候选隔离；另一个候选即使知道 artifact ID 也不能读取或引用该文件。
- 已生成上架草稿的候选不允许补传或改写证据，应新建候选修订，避免旧草稿引用新事实。

## 5. 系统校验与放行

生产评估只接受五个活动存档生成的规范引用。每次读取启动包、发布预检和 Commercial Alpha 预览都会检查：

1. artifact ID 存在且属于当前候选和正确证据类型。
2. 证据状态是 `active`，不是 `pending/superseded/orphaned`。
3. 当前文件大小和 SHA-256 与索引一致；文件被修改或缺失立即阻断。
4. 报价、库存、市场基线的候选时间与存档观察时间一致且未过期。
5. 候选批准指纹与当前证据修订一致。

Pi 的 `xianyu_candidate_evidence` 只读取上述脱敏元数据和完整性状态。Pi 不能上传、替换、下载证据，也不能批准候选。

## 6. 常见阻断处理

| 阻断 | 原因 | 操作者动作 |
|---|---|---|
| `archive_required` | 仍是路径、网址或自由文本引用 | 在证据存档区上传真实文件，不要手填引用 |
| `archive_missing` | artifact ID 不存在或不属于该候选 | 回到正确候选重新上传并绑定 |
| `archive_kind_mismatch` | 文件绑定到了错误证据类型 | 选择正确类型重新上传 |
| `archive_not_active` | 文件仍待绑定、已替换或绑定失败 | 查看活动文件；必要时重新采集并上传 |
| `integrity_failed` | 文件缺失、大小或哈希变化 | 不要修改 blobs；从真实来源重新采集并上传新证据 |
| `observed_at_mismatch` | 表单时间与存档观察时间不同 | 以真实存档观察时间为准，重新上传或更正事实 |
| `stale` | 报价/库存超过 24 小时，市场超过 72 小时 | 回到来源重新核验并上传当前证据 |
| `candidate_locked` | 候选已有 listing draft | 新建候选修订，不改写旧候选 |

## 7. API 和存储边界

控制台是默认写入入口。只读接口：

```text
GET /resale/candidates/{candidate_id}/evidence-artifacts
GET /resale/candidates/{candidate_id}/evidence-artifacts/{artifact_id}/file
```

上传接口使用原始文件字节，不使用 multipart：

```text
POST /resale/candidates/{candidate_id}/evidence-artifacts
  ?kind={evidence_kind}
  &observed_at={ISO-8601 time}
  &filename={original filename}
```

请求 `Content-Type` 必须与文件匹配；`note` 和 `source_url` 可作为额外查询参数。下载响应强制 attachment、`no-store` 和 `nosniff`。API 不提供删除或改写端点。

真实环境的候选记录位于 `data/live/resale_candidates.json`，证据索引与内容寻址文件位于 `data/live/candidate_evidence/`。备份或迁移时先停止服务，把候选文件和整个证据目录作为同一个一致性快照复制；恢复后先只读打开存档列表并检查每个活动文件的完整性，再启动实盘流程。不要单独复制索引或单独复制 blobs。

若误传了敏感文件，立即停止该候选的评审和发布并停止服务；当前应用没有在线删除接口，应按本地数据处置流程对一致性备份、索引和内容文件进行受控处理，再做完整性验收。不能继续把该 artifact 当作商业证据。
