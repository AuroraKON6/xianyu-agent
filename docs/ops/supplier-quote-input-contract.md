# 供应商报价输入约定

更新：2026-09-23。适用于现有 `/commerce/supplier-imports/preview` 与确认流程，不代表供应商、商机或交易已获批准。

## 导入前

1. 保留供应商原始文件与实际观察时间，不修改价格、库存或日期以通过校验。
2. 一个 SKU 一行，表头唯一。CSV 中含逗号的金额必须有 CSV 引号，例如 `"1,500.25"`。
3. 明确币种、报价单位，以及库存和起订量的数量单位。单位不一致必须先核实。
4. 先预览，核对原始字段、规范化字段和每行问题，再单独确认。`ok` 只表示本次解析没有发现歧义，不表示商业资料齐全。

## 字段

| 字段 | 示例 | 当前约束 |
| --- | --- | --- |
| `sku` / 货号 | 供应商自己的精确编码 | 不可空；同文件不能重复 |
| `price` / 单价 | `150.25` 或 `CNY 150.25` | 确定的非负十进制数；区间、起步价和科学记数法不猜测 |
| `currency` / 币种 | `CNY` | 明确外币转为 unknown，不自行换汇 |
| `unit` / 单位 | `pc`、件、`case`、箱 | 整箱价仅在装箱量确定时转单件价 |
| `pieces_per_case` / 装箱量 | `6` | 正整数，不接受小数、负数、范围 |
| `quantity_unit` / 数量单位 | `pc`、件、`case`、箱 | 共同描述库存和MOQ的原始数量单位；两者单位不同应先拆分整理 |
| `moq` / 起订量 | `2` | 正整数；`1.5`、`0`、`1-5`不能变成有效MOQ |
| `stock` / 库存 | `10` | 明确非负整数；小数、范围、说明文字中的数字不取整或截取 |
| `freight` / 运费 | `15`、包邮 | 到付或空白保持 unknown；负数拒绝该行 |
| `tier` / 阶梯价 | `10:145;50:140` | 阈值正整数且唯一；整组有歧义就不保留部分折扣 |
| `spec` / 规格 | 同一SKU的可交付规格 | 导入不会证明这些规格真实或已经同款匹配 |
| `source_kind` / 来源类型 | `supplier_original`、`demo`、`unknown` | `real`兼容为supplier_original声明；不是供应商真实性认证 |
| `source_reference` / 原始报价引用 | 原始取得记录的脱敏索引 | 必须非空；不自动访问该引用，不可用unknown等占位值代替 |
| `source_observed_at` / 实际观察时间 | 带时区的ISO时间 | 使用供应商实际报价/确认时间，不用文件修改时间或导入时间替代 |
| `valid_until` / 有效截止时间 | 带时区的ISO时间 | 必须晚于实际观察和当前评估时间；24小时最大年龄规则仍独立生效 |

为兼容既有国内人民币文件，未写币种仍沿用旧的 CNY 解释。新导入快照的 `attributes.import_basis.currency_assumed` 会记录这是缺少币种列的假设；**真实试运行必须另行核清，不能把默认值当成供应商确认**。

## 整箱换算

例如供应商单价为 `720 CNY/箱`、每箱6件：

- 规范化单价为120 CNY/件，快照价格单位同时变成单件单位。
- `quantity_unit=case`、MOQ=2、库存=10时，规范化MOQ=12件、库存=60件。
- `quantity_unit=pc`时，MOQ与库存已经是件数，不再乘装箱量。
- 没写数量单位，或装箱量不明时，不猜库存与MOQ；数量保持unknown，行进入 `needs_confirmation`。
- 阶梯价的单价按相同箱规转换，阈值按明确的数量单位转换。
- 运费**不随箱规自行除或乘**；文件中的运费必须已经对应拟评估的发货范围。按箱/按重量/按地区报价的运费应另行核清，否则用unknown。

转换依据保存在 `attributes.import_basis`，包括原始报价单位、数量单位、装箱量和币种。供应商改箱规或单位后必须重新预览，不沿用旧结果。

## 拒绝与待确认

- 重复表头、CSV多余单元格属于结构错误，拒绝整个文件，防止错列。
- 负价格、负运费或负数量拒绝该行，其他合法行仍可预览和确认。
- 区间价、外币、歧义数量、无依据的箱规换算保持unknown或 `needs_confirmation`。
- `include_needs_confirmation=true` 只是允许保存尚未核清的历史快照，不会把unknown改为零，也不授权采购或发布。
- 原始预览行号与价格无关；核对时使用行号与SKU，不依赖价格定位。

## 时间与来源门禁（R9已实现）

上述四列通过现有CSV、XLSX和粘贴表格进入不可变快照的`attributes.quote_provenance`。快照`observed_at`保留实际观察时间，`fetched_at`由程序记录导入时间，`expires_at`保留供应商声明期限。包含时间戳的粘贴CSV按表头识别，不把时间中的冒号误解析为键值对。

门禁统一由`quote_provenance`和`providers.freshness`判定：

- 缺失、无时区、未来或溢出的观察时间，缺失有效期/来源引用，或元数据与快照顶层时间不一致，均不可成为current报价。
- 当前时间到达`valid_until`即过期；即使供应商写了更长有效期，实际观察超过24小时仍不可用。
- 明确的`source=demo/fixture/synthetic`备注或来源标记优先于supplier_original声明，不能以改标签放行演示数据。
- 缺失实际时间时，为兼容旧快照必填字段，顶层`observed_at`可能保留导入时间作为历史占位；**资格判定始终检查独立来源元数据，不能据此获得新鲜度**。
- 历史快照及库存不自动迁移、不自动补成真实；旧库存缺少来源时间事实时可售为0，已有订单锁保留。应取得新证据后重新预览、确认和登记库存。
- 库存读取、锁定与服务重建后均重新检查有效期；商机重评估不通过时，已有ready_for_test转paused。没有新增定时重评估进程，不能把历史状态当作永久有效。
- Pi报价审查仍能看到committed的演示/未知报价以识别缺口，但输入带来源、时效、不可用原因和单独可用计数；这不授予外部模型数据使用权。
- 影子日志的total保留全部演练记录；`real_source_samples`仅统计观察时来源声明/时间合格且绑定有效批次与市场快照的事件。它是结构合格计数，不是供应商已认证或真实成交计数。
- 事件重放复用原裁决及来源事实；事后撤销不重写历史观察，使用前仍须检查当前状态。达7天/100条只是样本数量门槛，`autonomy_authorized`始终false。

## 真实试运行前仍需完成

1. 不能仅凭“导入成功/current/样本数达标”启动真实采购、发布或自动回复。
2. 真实报价还需满足供应商身份、精确SKU、运费范围、有效期、库存、税费、履约、售后条款及证据引用。来源标签本身不是真实性认证。
3. 复用[只读资料准入评估](../SUPPLIER_INTAKE_READINESS.md)核对原文件摘要、批次/快照绑定和声明缺口；`ready_for_human_review`不是持久审批，不能作为放行令牌。
4. 下一包把原始材料、人工核验身份、批准范围与有效期绑定到确切批次/快照版本，再接入只读任务输入。未知许可不能默认为可发给外部模型。
5. 完整单品资料继续复用 [Commercial Alpha 资料包](commercial-alpha-intake-bundle.md)，不要另建绕过现有11/12及人工审批的交易链路。

真实证据齐备、人工核验与只读复验通过之前，自动回复、上架、采购和退款保持关闭。
