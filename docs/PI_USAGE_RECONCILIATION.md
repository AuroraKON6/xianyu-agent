# Pi 未知消费人工对账

适用范围：本机单进程闲鱼服务。此功能只纠正已有attempt的未知token消费，不执行模型、不恢复job、不采纳决策、不操作平台。

## 默认关闭与操作者身份

只有启动服务时同时配置以下两项，对账接口才可用：

- `PI_USAGE_RECONCILE_OPERATOR`：负责核对的操作者标识。
- `PI_USAGE_RECONCILE_TOKEN_SHA256`：独立操作者令牌的SHA-256，64位十六进制。不是模型API Key。

服务读取启动环境或原有`.env`加载结果；改配置后需要由操作者正常重启服务。代码交付本身不会启用功能。

原始令牌应由操作者在密码管理器中生成和保存，使用不少于32字符的高熵随机值；不放进仓库、服务端`.env`、Pi子进程环境、URL、聊天或日志。服务端只需要哈希。可在本机隐藏输入计算哈希：

```powershell
.\.venv\Scripts\python.exe -c "import getpass,hashlib; print(hashlib.sha256(getpass.getpass('Operator token: ').encode('utf-8')).hexdigest())"
```

请求通过 `Authorization: Bearer <操作者原始令牌>` 认证。审计身份从服务端配置获取，请求体不接受operator字段。不要复制测试文件中的演示令牌。

Pi job token不是操作者凭证：携带 `X-Xianyu-Job-Token` 的请求一律禁止对账；不带job token也必须通过独立认证。配置哈希而非原始令牌，避免现有Pi环境变量传递机制直接泄露对账凭证。

这是单操作者凭证，不是多用户SSO、MFA或完整权限平台。保持服务仅监听本机回环地址，不应直接暴露公网。

## 三步工作流

### 1. 查找未结算attempt

`GET /commerce/pi-usage/unresolved`

返回未知消费列表。`reconcilable=false` 的旧格式无attempt记录、孤儿记录、仍leased/running的job不能通过本API直接清除。先核对运行状态，不能仅因超时就假定没有费用。

对于仍running的job，须先确认进程与租约事实，并通过既有任务恢复/取消流程处理。对账接口不替你取消正在执行的模型调用。

### 2. 核对证据并预览

`POST /commerce/pi-usage/preview`

请求结构示例，仅用于隔离演练，不代表真实费用：

```json
{
  "job_id": "替换为待核对job_id",
  "attempt": 1,
  "resolution": "settle",
  "total_tokens": 15,
  "idempotency_key": "operator-reconcile-example-001",
  "reason": "已由操作者核对原始用量报告与本次attempt的对应关系。",
  "evidence": {
    "kind": "provider_usage",
    "reference": "供应商请求号或已保存报告的索引",
    "job_id": "替换为同一job_id",
    "attempt": 1,
    "total_tokens": 15,
    "statement": "记录脱敏核对摘要，包括报告来源、对应关系和核对结果。"
  }
}
```

证据只保存脱敏摘要与引用，不粘贴密钥、Cookie或完整含密响应。job、attempt、tokens必须与证据字段一致。API不下载URL、不读取请求指定的文件路径、不主动查询供应商。

两种resolution：

- `settle`：凭供应商用量报告核对实际tokens，evidence.kind=`provider_usage`。允许确有证据的0，但不能用0表示未知。
- `release`：凭出站审计确认请求未发出，evidence.kind=`dispatch_not_sent`，tokens必须0。已有模型名称、job结果引用或该attempt决策产物时，接口拒绝“未出站”声明。没有产物本身并不能证明没有出站，操作者仍须核实原始记录。

预览返回原账本、预计状态、原业务日、服务端操作者、证据摘要哈希、`expected_state`与`approval_digest`。预览不写盘。

### 3. 明确确认并提交

人工检查预览后，向 `POST /commerce/pi-usage/reconcile` 提交原请求，增加预览返回的两个digest及 `confirmed: true`。不可只发送job_id和“清零”。

如果账本、job、证据、实际tokens或其他请求内容变化，旧确认失效；重新预览、重新核对。服务不会接受客户端伪造的operator字段。

成功回执包含原始状态、原业务日、实际tokens、resolution、身份、时间、证据、证据哈希、幂等键及请求摘要。账本更新和审计回执保存在同一JSON条目、同一次原子文件替换中。

## 重试与故障处理

| 响应 | 处理 |
| --- | --- |
| 200 | 保存receipt；同请求重放返回原receipt，`idempotent=true` |
| 401 | 缺失或错误的操作者凭证；不要使用模型Key代替 |
| 403 | job会话不可对账 |
| 404 | job/attempt不存在；不能创建虚构记录来解除门禁 |
| 409 | 执行中、状态变化、重复键冲突或证据与产物矛盾；先调查，必要时重新预览 |
| 422 | 字段、证据绑定或人工确认不满足合同 |
| 503 | 默认未配置/存储不可用；修复原因后用原幂等键与原请求重试 |

网络响应丢失时不要换幂等键：用同一请求重试。如果文件已成功替换，返回已存回执；若未写入成功，未知负债仍在。相同键但内容或身份不同返回409。

已settled/released的记录不能被本API再次降低消费。旧unknown、其他attempt的unknown仍会阻断。人工settle的tokens继续参加原业务日预算，不能用对账绕过日限。

## 浏览器人工对账面板（R8）

位置：现有 `/console` 页的商机区域，Pi任务台下面的“Pi 未知消费 · 人工对账”。不要点击上方“执行一个任务（真实 Pi）”来做对账；两条链路互相独立。

1. 服务仍默认关闭，先按本文配置独立操作者及凭证哈希；本批开发不修改实际 `.env` 或日常配置。
2. 仅在受信任设备、回环地址或已正确配置HTTPS的部署上打开面板。UI不替代部署认证、TLS、反向代理限制及单进程写入约束；不要在明文公网或共享浏览器中输入凭证。
3. 输入独立对账凭证，点击“解锁并读取”。不要输入DeepSeek API Key。凭证在解锁后立即从密码框清除，仅保留在当前页面闭包内存，用于这三个对账接口的Authorization头。
4. 列表显示原业务日、job、attempt及状态。活跃、孤立、缺失attempt等不可对账记录没有选择按钮，必须人工排查，不能新建假attempt解除门禁。
5. 选择记录后填写处理方式、实际`total_tokens`、证据引用、理由与核验说明。数字是tokens，不是人民币；unknown不能用0代替。选择释放时自动固定0，但仍须有未发送的独立证据。
6. 点击“只读预览差异”，核对前后状态、原业务日、实际消耗、服务端operator、证据及摘要。预览不落账；修改任意字段会撤销预览和勾选，必须重新预览。
7. 人工独立核验证据，勾选确认，再点击“确认并保存回执”。按钮防重复点击；只有收到与本次请求绑定的回执才显示成功。
8. 成功后可查看完整审计回执，刷新剩余未知列表。回执不等于job成功，也不代表所有预算门禁已经解除。

### 网络不明、锁定与重试

- 30秒无响应、网络中断、503或不完整/不匹配回执：结果一律不明。表单与列表刷新被冻结，原JSON请求和幂等键保持不变；按钮变为“以原请求重试 / 取回回执”。不会自动重新调用模型。
- 401/403要求用同一操作者凭证重新解锁；在结果不明时也可随时点击“锁定 / 清除凭证”，中断客户端等待并清除凭证，但不会保证服务端取消写入。原请求仍留在页面内存供同一操作者重试。
- 解锁后的列表可能已经没有该unknown，这不授权生成新请求；仍应点击原请求重试，服务端返回先前保存的回执。
- 404/409/422为明确拒绝：旧确认撤销，核对账本后重新预览。不能强制覆盖，也不能篡改其他尝试的金额或tokens。
- 结果不明时不要刷新、关闭或跳转；页面会尝试显示离开提示，但浏览器不保证一定展示。面板不向localStorage/sessionStorage/Cookie保存凭证或请求。页面离开即清除内存；强制离开后原请求可能丢失，须由操作者核查服务端原账本和已持久化receipt，不能把“列表里没有”当成未执行。
- 普通锁定清除面板数据与凭证。这里说的“不落盘”是应用不主动持久化，不保证操作系统交换文件、浏览器扩展、开发者工具或外部密码管理器不会记录内存/网络信息。

## 能证明与不能证明的内容

- 哈希证明本次确认与保存内容一致，不证明供应商报告真实。审计标识为`operator-attested; not provider-verified`，原报告由操作者负责保存和核对。
- 本地单进程互斥和原子文件替换，不是跨进程数据库事务或防管理员篡改的审计系统。禁止多个服务进程同时写同一数据根，禁止外部直接改JSON。
- 对账不意味着原job成功，不恢复其失效决策，也不会自动再次调用模型。
- R7交付API；R8增加浏览器对账表单与隔离真实浏览器测试。SSO、供应商自动核验、跨进程数据库事务及真实生产对账仍未交付/未验收。
